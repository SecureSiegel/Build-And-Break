# Lesson 01 - Review, Program Design, and Debugging

## Our goal

I will help you refresh the habits that make larger programs easier to build: understand the problem, define what goes in and what comes out, plan the design, then compile, test, and document.

## What I will teach

Writing code is only one part of programming. Before we type, we should identify the problem and describe the inputs and outputs. We can break the solution into steps or functions, then test whether the program handles expected and unexpected cases.

When something goes wrong, we will make the error reproducible, read the message, inspect the smallest relevant piece of code, and test a correction. We will not change several unrelated things at once.

## Guided steps

1. Choose a small task, such as adding all values in an array.
2. Write the problem in one sentence. List the inputs, output, and any limits.
3. Write the algorithm in plain language before coding.
4. Implement one step at a time. Compile after each meaningful change.
5. Test with a normal example, an empty or smallest case, and a boundary case.
6. Write down what the program does and how you tested it.

## Practice

- Take a program from Year 1 and describe its input, processing, and output.
- Introduce one small syntax error, read the compiler message, and correct it.
- Create a checklist for testing a program that calculates a total.

## Check for understanding

- Why define expected inputs and outputs before writing code?
- What is the difference between a compiler error and a program logic error?
- How does changing one thing at a time make debugging easier?
